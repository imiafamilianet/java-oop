# Personal Finance Manager (Система управления личными финансами)

Консольное backend-приложение на языке **Java** для учета личных доходов и расходов, планирования бюджета по категориям,
формирования финансовой аналитики и переводов средств между пользователями.

Проект разработан в рамках итогового задания по курсу **«Принципы объектно-ориентированного программирования»**.

---

## Основные возможности

* **Авторизация и многопользовательский режим:** регистрация и вход по логину и паролю. Данные каждого пользователя изолированы.
* **Учет операций:** добавление доходов и расходов с привязкой к категориям и комментариям.
* **Управление бюджетом:** создание пользовательских категорий и установка лимитов расходов на каждую категорию.
* **Аналитика и отчетность:** подсчет общих доходов/расходов, детализация по категориям, расчет остатка бюджета (включая отрицательный остаток при перерасходе).
* **Экспорт данных:** вывод отчетов в терминал или сохранение в текстовый файл.
* **Система оповещений:** мгновенные уведомления в консоли при превышении лимита бюджета по категории или при превышении общих расходов над доходами.
* **Переводы между пользователями:** перевод средств другому зарегистрированному пользователю по логину с автоматической фиксацией расхода у отправителя и дохода у получателя.
* **Сохранение состояния:** автоматическая сериализация кошелька в файл при выходе из аккаунта и загрузка при повторной авторизации.

## Архитектура проекта

Проект построен на принципах ООП (абстракция, инкапсуляция, наследование, полиморфизм) с четким разделением ответственности по пакетам:

```text
src/main/java/ru/my/corp/oop/
├── model/                        # Модели предметной области (Serializable)
│   ├── Category.java             # Модель категории операций
│   ├── Expense.java              # Модель расхода (наследник Operation)
│   ├── Income.java               # Модель дохода (наследник Operation)
│   ├── Operation.java            # Абстрактный базовый класс финансовой операции
│   ├── OperationType.java        # Перечисление типов операций (INCOME, EXPENSE)
│   ├── User.java                 # Модель пользователя (логин, пароль, кошелек)
│   └── Wallet.java               # Кошелек пользователя (баланс, операции, бюджеты)
├── service/
│   ├── ui/
│   │   └── ConsoleUI.java        # Консольный интерфейс, цикл команд и валидация ввода
│   ├── AuthService.java          # Интерфейс сервиса авторизации и регистрации
│   ├── AuthServiceImpl.java      # Реализация логики регистрации и входа
│   ├── FinanceService.java       # Интерфейс сервиса управления финансами
│   ├── FinanceServiceImpl.java   # Реализация расчетов, бюджетов, оповещений и переводов
│   ├── StorageService.java       # Интерфейс сервиса хранения данных
│   └── StorageServiceImpl.java   # Реализация сериализации пользователей в файлы
└── Main.java                     # Точка входа в приложение
```

## Требования и запуск

### Системные требования
* **JDK 17** или выше
* **Maven** или **Gradle** (для подключения зависимости `Lombok`)

### Инструкция по запуску
1. Клонируйте репозиторий на локальный компьютер:
   ```bash
   git clone https://github.com
   cd имя_репозитория
   ```
2. Соберите и запустите проект через IDE (IntelliJ IDEA) или с помощью Maven:
   ```bash
   mvn clean compile exec:java -Dexec.mainClass="ru.my.corp.oop.Main"
   ```
3. При первом запуске в корне проекта автоматически создастся директория `data/`, в которой будут сохраняться файлы кошельков пользователей (`<login>.dat`).

## Как пользоваться сервисом (Поддерживаемые команды)

Управление происходит в интерактивном цикле через ввод номера команды в консоли.

### 1. Меню авторизации (до входа в систему)

| Команда | Описание |
| :--- | :--- |
| `1` | **Войти** — авторизация существующего пользователя по логину и паролю с загрузкой его кошелька из файла. |
| `2` | **Зарегистрироваться** — создание нового аккаунта и инициализация кошелька с базовым набором категорий. |
| `0` | **Выйти из приложения** — завершение работы программы. |

### 2. Главное меню (личный кабинет)

| Команда | Описание |
| :--- | :--- |
| `1` | **Добавить доход** — запись поступления средств с указанием категории, суммы и комментария. |
| `2` | **Добавить расход** — запись траты с проверкой лимита бюджета и выводом предупреждений при перерасходе. |
| `3` | **Создать категорию** — добавление новой пользовательской категории доходов или расходов. |
| `4` | **Установить бюджет** — задание или изменение денежного лимита для категории расходов. |
| `5` | **Показать общую статистику** — вывод в терминал общих доходов, расходов и остатков бюджета по категориям. |
| `6` | **Сохранить статистику в файл** — экспорт полного финансового отчета в указанный текстовый файл (например, `report.txt`). |
| `7` | **Подсчитать сумму по выбранным категориям** — расчет суммы по списку категорий через запятую (с уведомлением, если категория не найдена). |
| `8` | **Перевести средства другому пользователю** — перевод денег по логину получателя (создает расход у отправителя и доход у получателя). |
| `9` | **Показать историю всех операций** — вывод хронологического списка всех транзакций с датой и временем. |
| `0` | **Выйти из аккаунта** — сохранение текущего состояния кошелька в файл и возврат в меню авторизации. |

## Как протестировать код

Ниже приведены базовые сценарии для проверки корректности работы всех модулей приложения.

### Сценарий 1. Проверка расчетов и бюджетов (контрольный пример)
1. Запустите приложение и зарегистрируйте пользователя (команда `2`, например, логин `alex`, пароль `1234`).
2. Добавьте доходы (команда `1`):
    * Категория: `Зарплата`, Сумма: `20000`
    * Категория: `Зарплата`, Сумма: `40000`
    * Категория: `Бонус`, Сумма: `3000`
3. Установите бюджеты на категории расходов (команда `4`):
    * Категория: `Еда`, Лимит: `4000`
    * Категория: `Развлечения`, Лимит: `3000`
    * Категория: `Коммунальные услуги`, Лимит: `2500`
4. Добавьте расходы (команда `2`):
    * Категория: `Еда`, Сумма: `300`
    * Категория: `Еда`, Сумма: `500`
    * Категория: `Развлечения`, Сумма: `3000`
    * Категория: `Коммунальные услуги`, Сумма: `3000` *(система выведет предупреждение о превышении лимита на 500.0)*
    * Категория: `Такси`, Сумма: `1500`
5. Выберите команду `5` (**Показать общую статистику**). Ожидаемый вывод в консоли:
   ```text
   Общий доход: 63,000.0
   Доходы по категориям:
   Зарплата: 60,000.0
   Бонус: 3,000.0
   Общие расходы: 8,300.0
   Бюджет по категориям:
   Коммунальные услуги: 2500.0, Оставшийся бюджет: -500.0
   Еда: 4000.0, Оставшийся бюджет: 3200.0
   Развлечения: 3000.0, Оставшийся бюджет: 0.0
   ```

### Сценарий 2. Проверка сохранения данных между сессиями
1. В личном кабинете нажмите `0` (**Выйти из аккаунта**).
2. В меню авторизации нажмите `1` (**Войти**) и введите логин `alex` и пароль `1234`.
3. Нажмите `5` — все ранее введенные операции, баланс (`54,700.00`) и бюджеты должны полностью восстановиться из файла `data/alex.dat`.

### Сценарий 3. Проверка переводов между пользователями
1. Зарегистрируйте второго пользователя (например, логин `maria`, пароль `1234`) и выйдите из аккаунта (`0`).
2. Войдите под первым пользователем (`alex`), выберите команду `8` (**Перевести средства**) и отправьте `5000` пользователю `maria`.
3. Выйдите из аккаунта `alex` и зайдите под `maria` — баланс `maria` увеличится на `5000.0`, а в истории операций (`9`) появится входящий перевод от `alex`.

### Сценарий 4. Проверка валидации и обработки ошибок
* Попробуйте ввести отрицательную сумму или текст вместо числа при добавлении расхода — приложение отклонит ввод и попросит повторить попытку.
* В пункте `7` выберите тип «Расход» и введите `Еда, НесуществующаяКатегория` — программа выведет уведомление о том, что категория не найдена, и корректно посчитает сумму по категории `Еда` (`800.0`).
